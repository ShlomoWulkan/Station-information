## מפתח Google Maps — צעדים בקונסולת Google Cloud

הסדר חשוב. הגבלה ראשונה עוצרת שימוש לרעה מיד; הפוך — האפליקציה נשברת בפער.

### 1. מגבלת מכסה יומית — ראשון

`APIs & Services` → `Maps SDK for Android` → `Quotas & System Limits` → הגדר
תקרה יומית (התחל ב-500 בקשות ביום).

זה הצעד היחיד ש**עוצר בקשות בפועל**. התראת תקציב רק שולחת מייל אחרי שהכסף
נשרף, ולכן היא לא תחליף. אם המפתח החשוף כבר נקצר מהרפו, זה מה שחוסם את הדימום.

### 2. הגבל את המפתח הקיים

`APIs & Services` → `Credentials` → המפתח → `Edit`:

- **Application restrictions**: `Android apps`
- הוסף: package name `com.midaatachana.app` + טביעת SHA-1 של מפתח החתימה
- **API restrictions**: `Restrict key` → `Maps SDK for Android` בלבד

לקבלת ה-SHA-1 של מפתח החתימה של EAS:

```powershell
cd mobile
eas credentials
# Android → production → Keystore → הצג את SHA-1 Fingerprint
```

מפתח מוגבל ל-package + SHA-1 בטוח יחסית גם כשהוא ידוע, כי הוא לא שמיש מחוץ
לאפליקציה החתומה שלך. הבעיה האמיתית הייתה מפתח **ללא** הגבלות.

### 3. הנפק חדש ומחק את הישן

צור מפתח חדש, הגבל אותו באותה צורה (צעד 2), עדכן את `mobile/.env`, ורק אחרי
שאימתת שהמפה עולה — מחק את הישן.

### 4. הזרקה לבילדים

```powershell
cd mobile
eas secret:create --scope project --name GOOGLE_MAPS_API_KEY_ANDROID --value <המפתח החדש>
```

### 5. התראת תקציב — רשת ביטחון שנייה

`Billing` → `Budgets & alerts` → תקציב עם התראות ב-50%/90%/100%.

## מודל העלות של Maps — חשוב לדעת

התמחור השתנה במרץ 2025, ואינטואיציה מלפני זה מסוכנת כאן.

עד אז טעינות מפה במובייל היו חינם ובלי הגבלה. **זה נגמר.** הצגת מפה מחויבת
היום תחת SKU בשם `Dynamic Maps`:

- **10,000 טעינות מפה בחודש — חינם**
- מעל זה — כ-**7$ ל-1,000** טעינות
- **חשבון חיוב פעיל נדרש** גם בשביל המדרגה החינמית

טעינה נספרת בפתיחת מסך המפה, לא בכל הזזה או זום. 10,000 בחודש ≈ 330 פתיחות
ביום. ב-1,000 משתמשים יומיים שפותחים מפה פעמיים זה מגיע לסדר גודל של מאות
דולרים בחודש — בלי שאף אחד תוקף, סתם מהצלחה.

הבקשות ל-`/stops` בהזזת המפה הולכות לשרת שלנו ולא לגוגל, ולא עולות כלום.

אם העלות תהפוך למשמעותית, החלופה היא MapLibre עם אריחי OpenStreetMap. שינוי
גדול, ולכן לא נעשה עכשיו — אבל עדיף לדעת מראש מלגלות מול חשבון.

## מפתח SIRI (משרד התחבורה)

**משרד התחבורה מאשר קריאות מ-`204.168.150.129` בלבד.** המפתח קשור ל-IP הזה.

השלכות:

1. `/arrivals` לא יכול לעבוד ממכונת פיתוח. פתח מול השרת (`EXPO_PUBLIC_API_URL`
   מצביע עליו) או דרך מנהרה: `ssh -L 5001:127.0.0.1:5000 <user>@204.168.150.129`.
2. **החלפת מכונה מחייבת רישום IP חדש מול משרד התחבורה.** אם בעוד שנה
   `/arrivals` יחזיר 401 אחרי פריסה למכונה אחרת — זו הסיבה, והמפתח לא פג.
3. אין דרך להריץ מכונה שנייה לגיבוי בלי לרשום גם את ה-IP שלה, ולכן ה-VPS הוא
   נקודת כשל יחידה. `Restart=always` ב-systemd הוא הכרח ולא נוחות.

המפתח נשאר בצד השרת ולעולם לא באפליקציה — אחרת כל אחד יחלץ אותו מה-APK. זו
הסיבה שהשרת קיים.
