## מפתח Google Maps — צעדים בקונסולת Google Cloud

### 1. הגבל את המפתח הקיים

`APIs & Services` → `Credentials` → המפתח → `Edit`:

- **Application restrictions**: `Android apps`
- הוסף: package name `com.stationinfo.app` + טביעת SHA-1 של מפתח החתימה
- **API restrictions**: `Restrict key` → `Maps SDK for Android` בלבד

**שניהם השתנו.** ה-package היה `com.midaatachana.app`, וה-SHA-1 גם הוא חדש: את
פרויקט ה-EAS היה צריך ליצור מחדש (ראה למטה), ופרויקט חדש מייצר keystore חדש.
אם ההגבלה בקונסולה עדיין מצביעה על הישנים, המפה תעלה ריקה בבילד חתום ובלי
שגיאה מדברת — התיקון הוא בקונסולה, לא בקוד.

**הוסף גם את ה-SHA-1 של keystore הדיבאג לאותה הגבלה.** `expo run:android` חותם
עם `android/app/debug.keystore` ולא עם המפתח של EAS, ולכן בלעדיו המפה תהיה ריקה
דווקא בבילד המקומי — כשל שקל לפרש בטעות כתקלה בקוד. הטביעה:

```
5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25
```

לקריאה חוזרת (`keytool` מגיע עם ה-JBR של Android Studio):

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -list -v `
  -keystore android\app\debug.keystore -alias androiddebugkey `
  -storepass android -keypass android
```

**מה ההגבלה הזו שווה:** כמעט כלום. `debug.keystore` מגיע מתבנית React Native,
והטביעה הזו זהה בכל פרויקט RN בעולם — כל אחד יכול לחתום APK עם `package`
`com.stationinfo.app` ולעבור אותה. ההגנה האמיתית כאן היא **הגבלת ה-API** ל-
`Maps SDK for Android` בלבד: היא מונעת שימוש במפתח מול שירותי גוגל אחרים, שכן
עולים כסף. ההידוק הנכון, כשמגיעים לבילד לחנות, הוא מפתח נפרד לפרודקשן שמוגבל
ל-SHA-1 של EAS ומוזרק ב-`eas env:set`.

לקבלת ה-SHA-1 של מפתח החתימה של EAS:

```powershell
cd mobile
eas credentials
# Android → production → Keystore → הצג את SHA-1 Fingerprint
```

מפתח מוגבל ל-package + SHA-1 בטוח יחסית גם כשהוא ידוע, כי הוא לא שמיש מחוץ
לאפליקציה החתומה שלך. הבעיה האמיתית הייתה מפתח **ללא** הגבלות.

### 2. הנפק חדש ומחק את הישן

צור מפתח חדש, הגבל אותו באותה צורה (צעד 1), עדכן את `mobile/.env`, ורק אחרי
שאימתת שהמפה עולה — מחק את הישן.

### 3. הזרקה לבילדים

`mobile/.env` הוא מקומי בלבד ולא מגיע לבילד בענן. `eas secret:create` ו-
`eas env:create` הוצאו משימוש, אחד אחרי השני. הפקודה הנוכחית:

```powershell
cd mobile
eas env:set --scope project --name GOOGLE_MAPS_API_KEY_ANDROID `
  --value <המפתח החדש> --environment production --environment preview `
  --visibility sensitive
```

`sensitive` ולא `plaintext`: הערך מוסתר בלוגים ובדשבורד, אבל עדיין נחשף לבילד.
`secret` היה מונע גם קריאה חזרה — ולא שמיש כאן, כי המפתח נצרב ל-manifest.

### 4. התראת תקציב — רשת ביטחון

`Billing` → `Budgets & alerts` → תקציב עם התראות ב-50%/90%/100%. לא בגלל המפה
(היא בחינם — ראה למטה), אלא כדי לתפוס שירות אחר שנדלק בטעות.

## פרויקט EAS — נוצר מחדש בשינוי השם

ה-slug השתנה מ-`midaa-tachana` ל-`station-info`, ו-project ID של EAS קשור ל-slug
יחיד **שלא ניתן לשינוי** ([expo.fyi/eas-project-id](https://expo.fyi/eas-project-id)).
לכן נוצר פרויקט חדש: `@sw323/station-info`, ID `e6ae7b4e-d5c0-4b14-953c-9cbbe353942a`.

מה שזה גורר:

- **keystore חדש** נוצר בבילד הראשון, ומכאן ה-SHA-1 החדש בצעד 1.
- הפרויקט הישן `@sw323/midaa-tachana` נשאר בדשבורד עם המפתח הישן. הוא לא בשימוש.
- זה היה אפשרי רק **לפני** פרסום. אחרי שהאפליקציה בחנות, חנות Play מקבלת עדכון
  רק מהחתימה המקורית, והחלפת keystore הופכת לבלתי אפשרית.

`app.config.js` הוא קונפיג דינמי, ולכן `eas init` לא יכול לכתוב אליו את ה-ID —
הוא מדפיס אותו וצריך להדביק ל-`extra.eas.projectId` ידנית. זה צפוי, לא תקלה.

## מודל העלות של Maps — המפה שלנו בחינם, ויש תנאי אחד

טעינות המפה כאן עולות **$0.00, ללא הגבלת נפח**. ה-SKU הרלוונטי הוא
`Mobile Native Dynamic Maps`, והוא מכסה אובייקט מפה שנטען דרך Maps SDK
ל-Android/iOS **בלי Map ID**. `map.tsx` משתמש ב-`<MapView>` נקי, בלי `mapId`
ובלי `customMapStyle`, ולכן הוא נופל שם.

**התנאי, וזו המלכודת:** ברגע שמוסיפים `mapId` — למשל כדי לעצב את המפה מהענן
ולהתאים אותה לצבעי האפליקציה — השימוש עובר ל-SKU `Dynamic Maps`: 10,000 טעינות
חודשיות חינם, ומעליהן כ-**7$ ל-1,000**. פיצ'ר עיצובי בן שורה אחת הופך לחשבון
חודשי, בלי שום סימן אזהרה בקוד. מי שנוגע בזה — שיקרא את הפסקה הזו קודם.

`Dynamic Maps` הוא גם ה-SKU שמצוטט ברוב הדיונים על "התייקרות מרץ 2025". הוא
מתאר את המסלול של **הווב**, ולא את שלנו.

מה שכן נשאר נכון בלי קשר:

- **חשבון חיוב פעיל נדרש** גם כשהמחיר אפס.
- הזזה וזום לא נספרים כטעינות חדשות.
- הבקשות ל-`/stops` בהזזת המפה הולכות לשרת שלנו ולא לגוגל, ולא עולות כלום.
- ההגבלה ל-`Maps SDK for Android` בלבד היא מה שמונע ממפתח דלוף לשמש מול שירותי
  גוגל אחרים — שם המחירים אמיתיים.

## מפתח SIRI (משרד התחבורה)

**משרד התחבורה מאשר קריאות מ-`204.168.150.129` בלבד.** המפתח קשור ל-IP הזה.

השלכות:

1. `/arrivals` לא יכול לעבוד ממכונת פיתוח. פתח מול השרת (`EXPO_PUBLIC_API_URL`
   מצביע עליו) או דרך מנהרה: `ssh -L 5001:127.0.0.1:5000 <user>@204.168.150.129`.
2. **החלפת מכונה מחייבת רישום IP חדש מול משרד התחבורה.** אם בעוד שנה
   `/arrivals` יחזיר 401 אחרי פריסה למכונה אחרת — זו הסיבה, והמפתח לא פג.
3. אין דרך להריץ מכונה שנייה לגיבוי בלי לרשום גם את ה-IP שלה, ולכן ה-VPS הוא
   נקודת כשל יחידה. `Restart=always` ב-systemd הוא הכרח ולא נוחות.

המפתח נשאר בצד השרת ולעולם לא באפליקציה — אחרת כל אחד יחלץ אותו מה-APK. זו
הסיבה שהשרת קיים.
